# Contributing to FullStage

FullStage aims to be approachable for church volunteers and rigorous enough for live-production operations.

1. Open an issue describing the change and its relevance to the [roadmap](docs/ROADMAP.md).
2. Work in a feature branch and submit a pull request against `main`.
3. Include tests and evidence for changes to output, cue, media, stage, or presentation state.
4. Never report browser-model tests as proof of real hardware output or native desktop integration.
5. Document upstream code origin, GPL obligations, and third-party content licenses.
6. Keep critical show controls accessible and support an opt-in fallback while replacing upstream UI.

Prioritize reproducible build steps, descriptive commits, accessibility and offline operation. No copyrighted media or Bible translations should be bundled without explicit redistribution permission.
